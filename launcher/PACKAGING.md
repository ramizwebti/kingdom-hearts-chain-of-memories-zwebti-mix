The `Package Windows release` workflow builds the single-file launcher on GitHub's hosted Windows runner. It never builds or runs a helper executable on the developer's computer and does not publish a release.

Attach `Kingdom-Hearts-Chain-of-Memories-Zwebti-Mix-0.11.0-runtime.zip` to the **draft** `v0.11.0` release in this repository. Both names follow `VERSION` and `RELEASE` in `launcher/build.py`; the workflow accepts no alternative repository, URL, tag or source branch. The ZIP must contain `runtime/guest-us.bin`, `runtime/rekhcom64.exe`, `runtime/SDL3.dll`, `runtime/assets/` and flat `licenses/` notices. Include the tested host and current canonical branding exactly: packaging refuses any runtime byte changes, including icon restamping. No game dump, save, profile, log or toolchain belongs in the input.

Dispatch `.github/workflows/package-windows.yml` from `main`, supplying the independently verified runtime ZIP's SHA256 as `runtime_sha256`. The job uses its short-lived repository-scoped GitHub token to fetch only the fixed asset. GitHub requires push access to read an unpublished draft, so only this guarded packaging job grants contents:write; the script performs read calls only, strips the token before building/running the launcher, and never publishes. It checks SHA256, ZIP CRC, bounded expansion, safe Windows paths and file exclusions before extracting under the clearly named Development folder. It then calls the existing launcher builder and checks every packaged file against its input.

The built launcher runs `--verify-install` twice in an isolated synthetic installation. The first invocation upgrades a synthetic 0.10.1 installation; the second checks an idempotent relaunch. Both preserve all synthetic Story/Practice/settings bytes and the prior version, and the installed payload must match the checked archive exactly. These checks require no ROM and do not claim a live network update or native combat validation.

The workflow also generates a fresh native source catalog from the same checkout. `Kingdom-Hearts-Chain-of-Memories-Zwebti-Mix-0.11.0-Native-Catalog.zip` contains only the searchable HTML, metadata JSON, coverage report, `NATIVE_CATALOG.md` and provenance. Provenance records the source commit, generator and input-manifest SHA256, counts, unresolved records and member hashes. No ROM or extracted artwork is read or included.

The workflow uploads exactly five deliverables: the versioned launcher EXE, release ZIP, ZIP checksum, native catalog ZIP and `packaging-manifest.json`. Input archives, build intermediates and synthetic profiles stay on the runner. Download and inspect the artifact before using Composure to publish these verified deliverables. Runtime and launcher hashes in the manifest identify precisely what was packaged; native combat results must refer to that same guest and host. The catalog's source commit is recorded separately from the unchanged tested runtime identity.
